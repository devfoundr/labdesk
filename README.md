# LabDesk

**B2B SaaS для зуботехнических лабораторий.** Учёт заказов от клиник, ведение производственных этапов, автоматическая генерация счетов и актов.

Работает в продакшене: [lab-desk.ru](https://lab-desk.ru) · Telegram: [@lab_desk](https://t.me/lab_desk)

> Продукт коммерческий, исходный код закрыт. Этот репозиторий — описание архитектуры и решений.

## Задача

Зуботехнические лаборатории ведут заказы в тетрадях, таблицах и переписке в мессенджерах. Когда лаборатория обслуживает десяток клиник и каждый заказ проходит через несколько техников и этапов, теряется всё: кто на каком этапе, что уже оплачено, сколько выставить клинике в конце месяца. Готовые CRM под это не ложатся — там нет понятия производственного этапа, прайса по видам работ и акта для клиники.

## Что внутри

**Заказы и производство**
Заказ от клиники с пациентом, врачом и составом работ. Движение по настраиваемым этапам производства, история изменений статусов, распределение работ между техниками.

**Прайс и ценообразование**
Прайс-лист по видам работ с категориями и артикулами. Сквозная нумерация артикулов: номера не переиспользуются после удаления. Архивирование позиций вместо удаления — архивные скрыты из прайса и подборщика, но остаются в исторических заказах и актах.

**Документы**
Автоматическая генерация счетов и актов по заказам за период, с построчной детализацией сумм по позициям. Печать актов без выгрузки в сторонние редакторы.

**Роли и доступ**
Разделение кабинетов: лаборатория, техник, клиника. Права на уровне строк в базе (RLS).

**Поддержка**
Встроенный чат: пользователи пишут из кабинета, ответы из админки. Уведомления в Telegram.

**Оповещения**
Раздел «Что нового» в кабинете и публичная справка для пользователей.

## Архитектура

| Слой | Решение |
|---|---|
| База данных | PostgreSQL (Supabase, self-hosted), схема с RLS-политиками |
| Аутентификация | Supabase Auth |
| Фронтенд | Vanilla JS + HTML, без сборки и фреймворков |
| Веб-сервер | Caddy (автоматический TLS) |
| Хостинг | VPS Ubuntu 24.04, Москва |
| Почта | Supabase Auth → Postfix → SMTP, свои шаблоны на русском |
| Интеграции | Telegram-бот через Cloudflare Worker как ретранслятор |

### Заметные решения

**Без фреймворка и без сборки.** Приложение — статические HTML/JS-файлы, которые отдаёт Caddy. Нет node_modules, нет шага сборки, деплой — это копирование файлов. Для продукта, который развивает один человек, это экономит больше времени, чем даёт любой фреймворк.

**Self-hosted Supabase вместо облака.** Данные российских медицинских организаций остаются в России, что снимает вопросы по 152-ФЗ. Плюс предсказуемая стоимость: VPS вместо оплаты за запросы.

**Своя почтовая цепочка.** Supabase Auth не проставляет заголовок Message-ID, и Gmail отклоняет такие письма. Решено прокидыванием через локальный Postfix, который добавляет корректные заголовки перед отправкой на SMTP-релей.

**Ретранслятор для Telegram.** С российских VPS `api.telegram.org` недоступен. Уведомления идут через Cloudflare Worker, который принимает запрос от сервера и передаёт его в Telegram.

**Миграция с Firebase на PostgreSQL.** Продукт начинался на Firebase/Firestore. С ростом требований к отчётности и реляционным связям (заказы → позиции → акты) документная модель стала мешать. Перенос на PostgreSQL сделан с сохранением работающих лабораторий.
